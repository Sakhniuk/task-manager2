# Лабораторна робота №3

## Порівняння з лабораторною роботою №2

У лабораторній роботі №2 проект вже був поділений на шари:
- Presentation
- Application
- Domain
- Infrastructure

Але вся application логіка знаходилась у use-cases.

Наприклад:
- CreateTask
- GetTasks

Use case одночасно:
- приймав дані
- виконував бізнес-логіку
- працював із repository

У лабораторній роботі №3 було реалізовано підхід CQS/CQRS.

Тепер операції запису та читання були розділені.

---

## Що змінилось у структурі проекту

| Lab2 | Lab3 |
|------|------|
| src/application/use-cases | src/application/commands |
| | src/application/command-handlers |
| | src/application/queries |
| | src/application/query-handlers |

Було створено:
- CreateTaskCommand
- CreateTaskHandler
- GetTasksQuery
- GetTasksHandler

Тепер кожна дія має окремий handler.

---

## Переваги CQS / CQRS

Основна перевага полягає у розділенні читання та запису.

### Commands:
- змінюють стан системи
- проходять через domain
- використовують валідацію

### Queries:
- тільки повертають дані
- не змінюють стан
- можуть бути простішими та швидшими

---

## Як це працює

У lab3 controller більше не містить логіки.

Тепер controller:
1. створює Command або Query
2. передає їх Handler

Схема роботи:
Controller → Command → Handler → Domain → Repository
Controller → Query → Handler → Repository

Такий підхід спрощує масштабування проекту.

## Відмінність Handler від Service

| Lab2 (Use Case) | Lab3 (Handler) |
|-----------------|----------------|
| виконував декілька задач одночасно | кожен Handler має тільки одну відповідальність |
| | CreateTaskHandler тільки створює задачу |
| | GetTasksHandler тільки повертає список задач |

Handlers стали меншими та простішими для тестування.

---

## Як CQRS впливає на розширюваність

| Lab2 | Lab3 |
|------|------|
| при додаванні нової функції потрібно було змінювати існуючі use-cases | можна просто додати новий Command, Query та Handler |
| | без зміни вже існуючого коду |

Це робить систему більш гнучкою та безпечнішою для розширення.

## Висновок

У лабораторній роботі №3 проект був переведений на CQRS архітектуру.

Основна відмінність від lab2 полягає у розділенні:
- операцій запису (Commands)
- операцій читання (Queries)

Commands відповідають за зміну стану системи, а Queries — тільки за отримання даних.

### Підсумок змін:

| Характеристика | Lab2 | Lab3 |
|---------------|------|------|
| Підхід | Use Cases | CQS/CQRS |
| Операції | змішані | розділені |
| Відповідальність | одна на use case | одна на handler |
| Тестування | інтеграційне | ізольоване |
| Розширюваність | зміна існуючого коду | додавання нового коду |

Проект став:
- більш масштабованим
- простішим для тестування
- більш гнучким для розширення

але кількість файлів та складність структури збільшились.
